Container Architecture vs. Virtual Machines

Understanding how virtualization differs at the OS level versus the Hypervisor level is core to container orchestration.

Feature Containers (e.g. Docker) Virtual Machines (VMs)
Virtualization Level Operating System level (Shares host kernel) Hardware level (Includes guest OS)
Weight & Startup Lightweight (seconds, megabytes) Heavyweight (minutes, gigabytes)
Isolation Process-level isolation (Namespaces, Cgroups) Strong hardware-level isolation (Hypervisor)
Efficiency High density, near-zero overhead Lower density, performance overhead

Understanding Image Layers

Docker images are constructed using read-only layers. Each instruction in a Dockerfile creates a new layer. This layout allows layer caching, reducing build times and network transfers.

Writable Container Layer (App States, Logs)
CMD ["gunicorn", "app:app"] (Layer 4)
COPY . /app (Layer 3)
RUN pip install -r requirements.txt (Layer 2)
FROM python:3.11-slim (Base Layer 1)

Access Control & Security (RBAC)

Azure utilizes Role-Based Access Control (RBAC) to enforce the principle of least privilege when interacting with ACR.

Owner / Contributor

Full access to manage the registry, including creating or deleting the registry instance itself and modifying admin credentials.

AcrPush

Grants permissions to build, tag, and push container images. Typically assigned to CI/CD pipelines (e.g., GitHub Actions, Azure DevOps).

AcrPull

Grants read access to search and pull container images. Assigned to hosting environments (ACI, AKS, Web Apps) to secure deployment workflows.

AcrDelete

Allows deletion of image repositories or specific tag manifests. Assigned to clean-up scripts or administrators.
